# 테스트 전략

## 1. 테스트 피라미드

### 단위 테스트 — 가장 많음

- Decimal 값 객체
- Candle 검증
- 타임라인 병합
- 리플레이 상태 머신
- 투자 계산
- 스케줄 생성
- 수익률·낙폭

### 계약 테스트

모든 MarketDataProvider 구현이 공통 계약을 만족하는지 검증한다.

### 통합 테스트

- Provider fixture → 정규화 → SQLite 저장 → 조회
- 세션 설정 → 데이터 준비 → 리플레이 → 시뮬레이션
- DB 마이그레이션

### UI 테스트

- 설정 검증
- 재생 제어
- 오류 상태
- 미래 데이터 비노출
- 키보드 조작

### E2E

웹 UI 수준은 Playwright MCP 또는 Playwright 테스트로 점검할 수 있다. 실제 Tauri 데스크톱 통합은 Tauri가 권장하는 현재 테스트 방식을 공식 문서에서 확인한 뒤 별도로 구성한다.

## 2. Golden fixtures

작고 사람이 직접 계산 가능한 고정 데이터셋을 만든다.

예시:

- 5일 가격: 100, 110, 90, 120, 120
- 일시투자 원금: 1,000
- 수수료: 0

기대 수량, 날짜별 평가액, 수익률, MDD를 문서와 테스트에 함께 둔다.

## 3. 독립 검증

금융 계산은 같은 구현을 다시 호출해 기대값을 만들면 안 된다.

- 손으로 계산한 fixture
- 별도 단순 기준 구현
- 스프레드시트 검산

중 하나 이상을 사용한다.

## 4. 회귀 방지

버그 수정 시 먼저 실패하는 테스트를 추가한다. 이후 구현을 수정한다.

## 5. 완료 게이트

기능 완료에는 다음이 모두 필요하다.

- 정상 경로 테스트
- 최소 하나의 경계 사례
- 오류 경로
- 관련 문서 갱신
- 전체 검증 통과

## 6. 성능 기준

초기 성능 목표:

- 자산 2개, 일봉 10년 범위를 일반 개발 PC에서 자연스럽게 준비·재생
- UI 메인 스레드가 긴 계산으로 눈에 띄게 멈추지 않음

측정 없이 Rust 또는 Worker로 조기 최적화하지 않는다.
