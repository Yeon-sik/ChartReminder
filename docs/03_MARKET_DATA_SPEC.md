# 시장 데이터 Provider 명세

## 1. 목표

서로 다른 공급자의 응답을 공통 `Instrument`와 `Candle`로 변환하고, 리플레이·시뮬레이션이 공급자 차이를 알 필요 없게 한다.

## 2. 암호화폐 수직 슬라이스

초기 공급자는 공개 일봉 캔들을 제공하는 거래소 API를 사용한다. 빠른 기본 추천은 BTC, ETH, SOL이며,
전체 탐색 목록은 Binance 공개 `exchangeInfo`에서 활성 SPOT·USDT 거래쌍을 동적으로 읽는다.
거래쌍과 quote currency는 UI에 명시한다.

예: `BTC/USDT`는 “비트코인 전체 시장의 유일한 가격”이 아니라 해당 공급자의 BTC/USDT 시장 가격이다.

## 3. 조회 정책

- 사용자가 요청한 전체 기간을 먼저 로컬 캐시에서 확인한다.
- 누락 범위만 공급자에게 요청한다.
- 페이지네이션 또는 최대 구간 제한을 Provider 내부에서 처리한다.
- 재시도는 제한된 횟수와 지수 백오프를 사용한다.
- Rate limit 응답은 일반 네트워크 오류와 구분한다.
- 부분 성공을 전체 성공으로 위장하지 않는다.
- 원시 응답 전체를 장기 저장할지는 별도 결정한다. 최소한 정규화 결과와 provenance는 저장한다.

## 4. 정규화 절차

1. 응답 스키마 검증
2. 심볼 및 통화 매핑
3. 타임스탬프를 UTC 밀리초로 변환
4. 거래일 산출
5. Decimal 문자열로 변환
6. OHLC 불변조건 검증
7. 중복 제거
8. 오름차순 정렬
9. 누락·부분 범위 메타데이터 생성
10. Repository 저장

## 5. Provider 계약 테스트

모든 Provider는 같은 계약 테스트를 통과해야 한다.

- 요청 범위 밖의 데이터를 반환해도 최종 결과가 올바르게 절단됨
- 역순 응답 정렬
- 중복 캔들 제거
- 잘못된 숫자 거부
- 페이지네이션 결합
- Rate limit 오류 매핑
- 빈 결과와 상장 이전 기간 구분
- 시간대 경계 검증

## 6. 미국 주식 추가 조건

- 수정주가와 원시 종가 의미를 분리한다.
- 분할·배당을 어떻게 반영했는지 표시한다.
- 거래소 휴장일을 캔들 누락 오류로 취급하지 않는다.
- 무료 API의 호출량·상업 이용·재배포 조건을 문서화한다.
- 공급자 종속 symbol mapping을 Provider 내부에 둔다.

## 7. 한국 주식 추가 조건

- 종목코드와 시장 구분을 지원한다.
- KST 거래일과 휴장일을 처리한다.
- 개인용 API 인증정보를 안전하게 보관한다.
- 제3자 배포 시 데이터 이용·재배포 허용 여부를 출시 게이트로 둔다.
- 이용조건이 불명확하면 기능을 공개 릴리스하지 않는다.

## 8. 캐시 무효화

과거 일봉도 공급자 정정, 주식 수정주가 갱신 등으로 달라질 수 있다.

캐시에는 다음을 저장한다.

- fetchedAt
- providerId
- schemaVersion
- adjustmentMode
- requestedRange
- completeRange

사용자가 수동 새로고침할 수 있어야 하며, 데이터 변경 시 세션 재현성을 위해 `dataVersion`을 보존한다.
